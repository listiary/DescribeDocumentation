## Description:
We now have an edit button for an article - at title of each list, when opened in the default site (Index module),
we have a link, called `edit`. We also have the option at the end of the page - the `</>` button.
But, for larger lists, it can be cumbersome, because the user needs to scroll all the way up or down,
hit edit, and scroll to the place he/she wants to edit.
<br><br>
Larger lists often have sections - delimited by an empty item, often starting with a special comment,
that will be tagged as {section} or something, and ending with the first plank line (item - blank lines are empty items in Describe)
<br><br>
It can be nice if we have a button to edit after each section's comment.
It can be hidden, and appear on mouseover - very much the same way as some wiki systems display a link icon 
next to a section of content when hovered over.
<br><br>
That edit control (probably the icon with the pencil) can either open an editor with just that section in it - 
that is editing files by piece, or just open the entire file, auto-scrolled to the section in question.
<br><br>
I think the former approach will introduce complexity, and the latter is the more easy and sensible implementation,
and we might choose to implement the former approach much later, if at all, but we should implement the latter.
